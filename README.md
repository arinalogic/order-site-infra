# order-site-infra

Учебный проект MVP системы обработки заказов на одном VPS с Ubuntu 22.04. Сервисы запускаются в Docker Compose. Реализованы Nginx, FastAPI backend, PostgreSQL, frontend и админ-панель Части 3.

## Сетевые порты

Наружу VPS опубликован только один порт:

| Порт | Назначение |
| --- | --- |
| `80` | Сайт, админка и API через Nginx |

PostgreSQL, backend, pgAdmin, Docker Registry и Watchtower собственные порты на хосте не публикуют. Сервисы доступны друг другу через внутреннюю сеть Docker.

Требуются Docker и плагин Docker Compose.

## Запуск

Шаги 2 и 3 выполняются на компьютере, остальные на VPS из корня проекта (`/root/order-site-infra`).

1. Создайте файл окружения:

   ```bash
   cp .env.example .env
   nano .env
   ```

   Укажите значения переменных PostgreSQL и задайте `SECRET_KEY` для подписи JWT. Создать ключ можно так:

   ```bash
   openssl rand -hex 32
   ```

   Не используйте `CHANGE_ME` в качестве пароля или ключа.

2. Соберите frontend на компьютере с Node.js и npm:

   ```bash
   cd frontend
   npm install
   npm run build
   ```

3. Передайте на сервер каталог `backend`, собранный `frontend/dist` и `docker-compose.yml`. Файл `.env` остаётся на сервере (создан в шаге 1) и не копируется. Пример:

   ```bash
   scp -r backend <ssh-имя-сервера>:/root/order-site-infra/
   scp -r frontend/dist <ssh-имя-сервера>:/root/order-site-infra/frontend/
   scp docker-compose.yml <ssh-имя-сервера>:/root/order-site-infra/
   ```

4. На сервере соберите backend и запустите сервисы:

   ```bash
   docker compose up -d --build
   docker compose ps
   ```

pgAdmin и Docker Registry не запускаются основной командой из-за профиля `tools`.

5. Откройте `http://<SERVER_IP>/admin.html` и зарегистрируйте первого администратора (логин, почта, пароль не короче 8 символов). После этого кнопка регистрации исчезнет.

## Часть 3: админ-панель и метрики

Админ-панель доступна по адресу `/admin.html`. Вход выполняется по логину и паролю; backend выдаёт JWT. Кнопка регистрации показывается, пока в базе нет ни одного администратора.

В админ-панели можно добавлять, редактировать и удалять услуги с диапазонами бюджета.

На главной собираются метрики поведения посетителей: для каждого визита создаётся одна запись в `behavior_metrics`, данные отправляются раз в секунду. Окно «Статистика пользователей» показывает среднее время на странице за день, неделю и месяц, популярные кнопки и карту активности курсора.

Список заявок доступен авторизованному администратору. Для каждой заявки браузер вычисляет «температуру» лида по названию услуги и другим полям заявки, а окно «Просмотр» показывает все данные заявки.

Правила оценки заявок:

| Критерий | Баллы |
| --- | --- |
| Срок: срочно / в течение месяца / в течение квартала | 30 / 20 / 10 |
| Срок не срочно или пустой | 0 |
| Команда: более 200 / 51–200 / 11–50 / до 10 человек | 15 / 12 / 8 / 4 |
| Объём задачи: крупный / средний / небольшой | 15 / 8 / 3 |
| Роль: руководитель / сотрудник | 10 / 4 |
| Заполнены телефон или email | 5 |
| Бюджет в диапазоне услуги | от 0 до 25 пропорционально позиции в диапазоне |
| Пустой или некорректный бюджет, услуга или диапазон | 0 баллов за бюджет |

Максимум — 100 баллов: 70 и выше — «Горячий», 40–69 — «Тёплый», ниже 40 — «Холодный».

## База данных

Backend при запуске создаёт таблицы:

- `admin_settings` — услуги и диапазоны бюджета;
- `applications` — заявки;
- `behavior_metrics` — записи поведения посетителей, обновляемые по одному идентификатору сессии;
- `admins` — учётные записи администраторов.

## Nginx и API

Через Nginx разрешены только следующие адреса `/api/`:

| Адрес | Разрешённые методы |
| --- | --- |
| `/api/admin-settings/` | `GET`, `POST` |
| `/api/admin-settings/[0-9]+` | `PUT`, `DELETE` |
| `/api/applications/` | `GET`, `POST` |
| `/api/applications/[0-9]+` | `GET` |
| `/api/auth/check` | `GET` |
| `/api/auth/me` | `GET` |
| `/api/auth/login` | `POST` |
| `/api/auth/register` | `POST` |
| `/api/behavior-metrics/` | `POST` |
| `/api/behavior-metrics/summary` | `GET` |
| `/api/behavior-metrics/heatmap` | `GET` |

Вход и регистрация ограничены 5 запросами в минуту с одного адреса. Метрики ограничены 3 запросами в секунду с одного адреса. При превышении лимита входа, регистрации или метрик Nginx возвращает `429`. Тело запроса метрик ограничено 64 КБ.

Все остальные адреса `/api/`, включая `/api/docs`, возвращают `404`.

## Docker-журналы

Для всех сервисов Docker Compose используется драйвер `json-file` с ротацией:

- `max-size`: `10m`;
- `max-file`: `3`.

Посмотреть журналы можно командой:

```bash
docker compose logs
```

## Отключённые сервисы

pgAdmin и Docker Registry в Части 3 отключены:

- у контейнеров в `docker-compose.yml` установлен профиль `["tools"]`;
- основная команда запуска не создаёт и не запускает эти контейнеры;
- порты `5050` и `5000` не публикуются;
- server-блоки для pgAdmin и Registry удалены из `nginx/conf.d/default.conf`.

Для возврата их в конфигурацию нужно отдельно вернуть порты и server-блоки в `default.conf`. Версия конфигурации с pgAdmin и Registry (до их отключения) доступна в истории Git в коммите `eb650d1`.

## Проверка работы

- Откройте `http://<SERVER_IP>/` — должна ответить основная страница со статусом `200`.
- Проверьте список заявок без токена:

  ```bash
  curl -i http://<SERVER_IP>/api/applications/
  ```

  Ответ должен быть `401 Unauthorized`.

- Проверьте, что порты `8000`, `5432` и `5050` снаружи недоступны. Например:

  ```bash
  nc -zv <SERVER_IP> 8000
  nc -zv <SERVER_IP> 5432
  nc -zv <SERVER_IP> 5050
  ```

- Для проверки оценки заявок добавьте тестовые данные: файл `docs/test-applications.sql` содержит 10 вымышленных заявок (4 горячих, 3 тёплых, 3 холодных). Выполните его один раз через `psql` в контейнере `postgres` или в любом SQL-клиенте.

- Если сервис не отвечает, проверьте `docker compose ps` и журналы сервисов.

## Файрвол UFW

На тестовом сервере ufw не включён. Внешний доступ ограничен фактически опубликованными Docker-портами: опубликован только порт `80`.

Для постоянного использования ufw предварительно разрешите порт SSH и затем включите файрвол:

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw enable
sudo ufw status
```

Docker публикует порты сам; настройки firewall дополнительно проверялись только для описанного тестового состояния.

## Ограничения

- HTTP без домена и HTTPS: пароль и JWT-токен входа передаются открытым текстом.
- JWT-токен хранится в `sessionStorage` браузера.
- Регистрация первого администратора открыта, пока в базе нет ни одного администратора.
- Backend работает от имени `root` внутри контейнера.
- Версии Python-библиотек не закреплены.
- Автоматической очистки старых метрик нет; действуют только лимиты и ограничения метрик в Nginx.
- Оценка заявок считается в браузере по названию услуги: при переименовании услуги баллы за бюджет в старых заявках будут равны `0`.
- Watchtower настроен на обновление только помеченных метками контейнеров, но метки сервисам проекта не назначены, поэтому ничего не обновляет.

## Безопасность

- Пароли и другие параметры окружения задаются в `.env`; файл исключён из Git через `.gitignore`.
- Backend и PostgreSQL не публикуют порты на хосте.
- Watchtower получает доступ к `/var/run/docker.sock`, что предоставляет ему широкие возможности управления Docker на хосте.
